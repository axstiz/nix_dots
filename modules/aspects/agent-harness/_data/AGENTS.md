# Глобальные правила для OpenCode

## Общие принципы

- Всегда отвечай на русском языке.
- Придерживайся минимализма в коде. Избегай избыточных inline-комментариев.
- Используй docstrings и документирующие комментарии только там, где это действительно необходимо для понимания интерфейса или сложной логики.

## Планирование и организация работы

Перед тем как начать писать код:

1. Проведи рефлексию по теме задачи.
2. Задай уточняющие вопросы, если что-то неясно.
3. Предложи перейти в режим планирования (Plan agent) для обсуждения подхода.
4. Совместно со мной сформируй чёткий план действий.
5. На основе плана создай TODO-лист с конкретными, измеримыми и отслеживаемыми пунктами.

Требования к TODO:

- Каждый пункт должен быть чётким и проверяемым.
- Избегай расплывчатых формулировок вроде "улучшить код" или "поработать над модулем".
- Каждый пункт должен соответствовать логическому блоку работы.
- Если невозможно сформулировать чёткие критерии для пункта — немедленно сообщи об этом мне.

## Разработка и тестирование

Для серьёзных проектов придерживайся TDD-подхода:

1. Детально выясни требования.
2. Вместе со мной определи метрики оценки результата.
3. Напиши тесты, учитывающие эти метрики.
4. Только после этого пиши код, который проходит тесты.

После завершения каждого логического блока сообщи мне, чтобы я мог сделать коммит по правилам и соглашениям о коммитах.

## Безопасность и секреты

- Ты не имеешь права читать или изменять файлы секретов: `.env`, `.env.*`, файлы в `secrets/`, `*-secrets/`, `.secrets/`, а также ключи, токены и сертификаты.
- При необходимости создавай только `example.env` или подобные шаблоны без реальных значений.

## Работа с окружением и командами

### Общие правила

- Если команда не найдена в текущем окружении, попробуй запустить её через `nix-shell` или внутри `nix develop`.
- Если ты сталкиваешься с ошибкой не в коде проекта, а в системе (отсутствует инструмент, внешняя команда падает, проблемы с окружением) — немедленно сообщи об этом мне и передай управление. Не пытайся скрыть системную проблему или продолжать работу в нерабочем окружении.

### Python и uv

- Для работы с Python-проектами я использую `uv2nix` в flake.nix. Я могу специально добавить flake.nix в gitignore.
- При добавлении зависимостей через `uv` виртуальное окружение не обновляется автоматически внутри запущенного OpenCode.
- В таких случаях ты должен либо попросить меня перезапустить OpenCode в новом виртуальном окружении, либо выполнить команду через инструменты Nix (например, `nix develop`), чтобы она запустилась в актуальном devShell.
- Это ограничение не распространяется на Rust-проекты и на запуск через Docker.
